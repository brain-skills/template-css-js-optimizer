# Template CSS/JS Optimizer

Браузерный инструмент [Mega Digital Studio](https://megadigital.studio/) для поиска неиспользуемых записей CSS и JavaScript относительно **всех HTML-страниц выбранного шаблона**, удаления выбранных неиспользуемых записей и скачивания подготовленной копии.

Загрузка, результаты и действия с файлами находятся на одном экране. Программа работает локально или на статическом HTTPS-хостинге — без Node.js, PHP, установки зависимостей, AI и ключей API.

## Быстрый запуск

1. Скачайте и распакуйте комплект.
2. Откройте `index.html` в современном Chrome или Edge.
3. Нажмите **«Пример проверки шаблона»**, чтобы попробовать инструмент без своих файлов, либо выберите ZIP/папку своего шаблона.

Встроенный пример содержит две HTML-страницы, CSS и JS с используемыми и неиспользуемыми записями. Он проходит через тот же обработчик, что и загружаемые шаблоны.

Для размещения на сервере достаточно статического хостинга. В `index.html` уже встроены стили, код обработчика, логотип и favicon. Отдельные SVG приложены как брендовые ресурсы; изменение этих отдельных файлов само по себе не обновляет встроенные копии в HTML.

## Возможности

- Импорт ZIP или папки с сохранением вложенных путей и выбором области проверки.
- Проверка всех HTML выбранной области, в том числе страниц без ссылок из меню, и найденных зависимостей.
- Общая таблица CSS/JS, поиск, фильтры библиотек и исправленных файлов.
- Удаление подтверждённых неиспользуемых записей во всех файлах или ручной выбор записей конкретного файла.
- Независимая отмена изменений каждого файла.
- Скачивание исходного файла, исправленного файла, всех исправлений или всего шаблона в ZIP.
- Читаемое представление кода и выбор beautify/minify при экспорте.
- Сравнение Bootstrap, Font Awesome и Foundation с оригиналами той же версии.
- Общие `custom.css`/`custom.js` с сохранением исходных записей и отдельным учётом вклада каждой библиотеки.

## Как работать

1. Выберите ZIP или папку. Если внутри несколько вариантов шаблона, выберите нужную область. Для общей проверки выбирайте весь источник.
2. Нажмите **«Проверить CSS и JS»**. Таблица заполнится на том же экране.
3. Посмотрите размеры, цветные полосы и найденные записи.
4. Удалите выбранные неиспользуемые записи. Все исправления накапливаются в одной рабочей копии.
5. Скачайте нужные файлы или нажмите **«Скачать весь готовый шаблон»**. Общий ZIP включает HTML, CSS, JS, изображения и остальные ресурсы выбранной области с текущими исправлениями.

У каждой строки постоянно видны четыре основные кнопки:

| Файл | Основное действие | Остальные действия |
| --- | --- | --- |
| Обычный CSS/JS | Удалить неиспользуемые записи | Скачать исходный · Скачать исправленный · Вернуть исходный |
| Библиотека | Получить оригинал | Скачать исходный · Скачать исправленный · Вернуть исходный |

Недоступные действия показаны неактивными с пояснением. Исходный ZIP и папка не перезаписываются. Перед закрытием вкладки скачайте результат: рабочие файлы хранятся в памяти текущего сеанса.

**Общая кнопка удаления** открывает обзор файлов: сколько записей подтверждено для автоматического удаления и сколько требуют ручной проверки. Если подтверждённых записей нет, кнопка остаётся доступной при наличии записей для проверки. В обзоре можно открыть нужный файл и выбрать записи; автоматическое удаление не включает неподтверждённые участки. Если записей для удаления или проверки больше нет, кнопка становится недоступной.

**Файлы с картой исходников.** При удалении записей из такого CSS/JS инструмент заранее предлагает отключить ссылку на прежнюю карту в исправленном файле. Это отдельное подтверждение: карта предназначена для отладки и после изменения кода больше ему не соответствует. Исходный файл и сам `.map` сохраняются, новая карта не создаётся. Для отладки исправленного кода её нужно собрать отдельно. «Вернуть исходный» восстанавливает и прежнюю ссылку. Отдельно скачанный исправленный файл и этот же файл в общем ZIP совпадают при сохранении текущего формата.

## Что означают цвета

| Цвет | Значение |
| --- | --- |
| Зелёный | Найдены статические обращения или упоминания в исходниках шаблона. |
| Оранжевый | Применение не найдено. Динамическое использование ещё возможно. |
| Серый | Применение не определено. |

Проценты рассчитаны по байтам кода до ZIP-сжатия. Это **статический анализ**, а не запись выполнения сайта: все взаимодействия пользователя автоматически не проигрываются. Оранжевая часть не является гарантированно безопасной для удаления.

Автоматическое удаление использует только подтверждённые движком участки. Для ручного удаления неподтверждённых записей требуется отдельное разрешение для конкретного файла. После таких изменений нужно проверить реальные сценарии шаблона. JavaScript проверяется по синтаксическому дереву; это не заменяет функциональную проверку сайта.

## Оригиналы библиотек и custom-файлы

Собственные `main.css`, `style.css`, `custom.js` и другие файлы не становятся библиотеками из-за упоминания Bootstrap, Font Awesome или Foundation в комментарии, подключении, коде либо названии папки. Распознавание использует стандартное имя файла библиотеки или отдельный начальный заголовок продукта с версией. Для собственных файлов доступно «Удалить неиспользуемые записи».

**«Получить оригинал»** использует официальный npm-пакет точной версии, проверяет контрольную сумму архива и выбирает соответствующий CSS/JS-файл. Не подставляется `latest` или другая сборка. Если версия или файл не определены либо пакет недоступен, операция останавливается; для известных точных версий можно выбрать оригинал вручную. Pro-сборки Font Awesome нельзя заменять бесплатными.

Самостоятельные добавления после точного оригинала переносятся как код в общие `custom.css`/`custom.js`. Если в шаблоне уже есть один подходящий custom-файл, его исходное содержимое сохраняется. При неоднозначных или защищённых путях выбирается отдельный незанятый путь.

Вклады библиотек учитываются отдельно. Отмена Font Awesome убирает только его добавления, сохраняя прежние записи custom и вклад других библиотек. Повторное получение оригинала не дублирует добавления.

**Внутренние изменения библиотеки не всегда можно безопасно вынести как исполняемый код.** Они сохраняются в custom как закомментированный контекст «было/стало» для разработчика. Полные изменённые файлы включаются в `optimizer-library-backups` внутри ZIP. Разработчик проверяет подключение custom, порядок выполнения, каскад и относительные URL. При восстановлении библиотек полная сборка обновляет связанные значения `integrity` в HTML.

## Данные, требования и ограничения

- Шаблоны обрабатываются в браузере и не отправляются на сервер или AI-сервис.
- Интернет используется для получения оригиналов из `registry.npmjs.org`. Для проверки их контрольных сумм нужен HTTPS или локально открытый HTML.
- Требуются Web Workers, Compression/DecompressionStream и Web Crypto для официальных пакетов.
- Основные лимиты: ZIP до **64 МБ**, папка/распаковка до **128 МБ**, до **20 000 файлов**, отдельный файл до **32 МБ**. Полный разбор CSS/JS — до **4 МБ** на файл, форматирование — до **1 МБ**. Файлы, не прошедшие полный разбор, не изменяются автоматически.
- ZIP64, шифрование, опасные пути и символические ссылки не поддерживаются. Вложенные ZIP автоматически не распаковываются.
- При своей Content Security Policy хостинг должен разрешать встроенные скрипты/стили, Blob Workers и `connect-src https://registry.npmjs.org`.

Обработчик и сценарии интерфейса проверены автоматическими тестами. Реальный визуальный прогон Chrome/Edge и живой запрос к реестру из браузера в среде подготовки этого комплекта не выполнялись; сетевой обработчик проверен на контрольных пакетах с SHA-512/TAR/GZIP.
